# RT-26. unsafe-libyaml 0.2.11 reached through serde_yaml 0.9.34, which is
# itself deprecated. The migration to serde_yaml_bw 2.5.8 (which drops
# libyaml) was attempted across 13 files and the manifests, then REVERTED: a

# path-tracked errors and strict scalars, which is a larger change. An owner
# decision, recorded in AD-033.
unmaintained|RUSTSEC-2024-0449|unsafe-libyaml@0.2.11

# --- triaged 2026-11-20 (iter-2711, RT-615) -----------------------------------
# RT-615. libsqlite3-sys 0.30.1 bundles SQLite < 3.54.0, which can return
# uninitialized page-cache memory when a database is opened beside a `-wal`
# sibling whose page size differs. REACHABLE here: rusqlite is built with
# `features = ["bundled"]` in operant-core, operant-cli and operant-os, and
# `cargo tree -e features -i libsqlite3-sys` shows the bundled feature
# arriving through memory-wire's default features. No semver-compatible fix
# exists (0.30.1 is the only 0.30.x; the fix is >= 0.40 via rusqlite >= 0.40,
# an API-breaking major bump across 99 rusqlite call sites in 3 crates). The
# attack needs the victim to OPEN a crafted database/-wal pair locally, and
# operant's sqlite files are created and written by operant itself under
# $OPERANT_HOME, not imported from an untrusted source. The major bump is
# recorded as its own scoped follow-up. Re-check at each rusqlite release.
vulnerability|RUSTSEC-2026-0459|libsqlite3-sys@0.30.1
